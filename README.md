# Georgetown Signal v2

> Georgetown, Texas's trusted local intelligence platform.
> Real recommendations from real community conversations.

**Stack:** Next.js 14 (Vercel) · Django 5 (Render) · PostgreSQL + Auth (Supabase) · Redis (Render) · Celery

---

## Architecture Overview

```
┌─────────────────────────────────────────────────┐
│  Next.js Frontend (Vercel)                       │
│  - Public directory, news hub, request form      │
│  - Vendor signup / login (Supabase Auth)         │
│  - Vendor dashboard (JWT-protected)              │
└─────────────┬───────────────────────────────────┘
              │ REST API (Bearer JWT)
┌─────────────▼───────────────────────────────────┐
│  Django API (Render)                             │
│  - Public endpoints: businesses, news, signals   │
│  - Vendor endpoints: JWT-authenticated           │
│  - Celery workers: score recalc, newsletter      │
└─────────────┬───────────────────────────────────┘
              │ PostgreSQL
┌─────────────▼───────────────────────────────────┐
│  Supabase                                        │
│  - auth.users (vendor accounts)                  │
│  - All tables with RLS policies                  │
│  - Auto-creates vendor_profiles on signup        │
└─────────────────────────────────────────────────┘
```

## Badge System

Badges are computed from explicit boolean fields. Two are admin-only, two are automatic.

| Badge | Field | How it's set |
|-------|-------|-------------|
| ⭐ Featured | `is_featured` | **Admin only** — paid upgrade |
| 🛡 Signal Verified | `is_verified` | **Admin only** — after vetting |
| 👥 Community Trusted | `is_community_trusted` | **Auto** — when `mention_count >= 10` |
| ⚡ Fastest Responder | `is_responsive` | **Auto** — when `avg_response_minutes < 45` |

Auto flags are recalculated every 6 hours by Celery. Admin flags are never touched by automation.

## 1. Supabase Setup

### 1.1 Create project
1. [supabase.com](https://supabase.com) → New project → name: `georgetown-signal`
2. Wait for provisioning (~2 min)

### 1.2 Run schema
SQL Editor → New query → paste `backend/supabase_schema.sql` → Run

### 1.3 Get credentials
- **Settings → Database → URI** → `DATABASE_URL`
- **Settings → API → Project URL** → `SUPABASE_URL`
- **Settings → API → anon public** → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- **Settings → API → service_role** → `SUPABASE_SERVICE_KEY`
- **Settings → API → JWT Secret** → `SUPABASE_JWT_SECRET`

### 1.4 Configure Auth
- **Authentication → URL Configuration**
  - Site URL: `https://georgetownsignal.com`
  - Redirect URLs: `https://georgetownsignal.com/auth/callback`

## 5. Vendor Flow (end-to-end)

1. Vendor visits `/auth/signup` → fills name, email, password
2. Supabase sends confirmation email → vendor clicks link
3. `/auth/callback` exchanges code → redirects to `/vendor/onboarding`
4. 4-step onboarding form: profile → business details → contact → review
5. Submission creates listing with `is_pending_review=True`
6. Admin reviews in Django Admin → bulk action "Approve listing"
7. `is_pending_review` → `False` → listing appears publicly
8. Admin can grant `is_verified` and `is_featured` via bulk actions
9. Celery auto-sets `is_responsive` and `is_community_trusted` every 6h

## 6. API Reference

Base: `https://georgetown-signal-api.onrender.com/api/`

### Public endpoints
| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/businesses/` | Directory (filter: `?category_slug=electricians&is_verified=true`) |
| GET | `/businesses/{slug}/` | Business detail |
| GET | `/businesses/{slug}/reviews/` | Community reviews |
| GET | `/signals/ticker/` | Live ticker strings |
| GET | `/news/` | Published news posts |
| GET | `/news/{slug}/` | News article |
| GET | `/stats/` | Platform stats |
| POST | `/leads/` | Submit service request |
| POST | `/newsletter/subscribe/` | Subscribe to newsletter |

### Vendor endpoints (require `Authorization: Bearer <supabase_jwt>`)
| Method | Endpoint | Description |
|--------|----------|-------------|
| GET/PATCH | `/vendor/profile/` | Read/update vendor profile |
| GET/POST | `/vendor/businesses/` | List own businesses / create new |
| GET/PATCH | `/vendor/businesses/{id}/` | Read/update specific business |
| POST | `/vendor/onboarding/` | Mark onboarding complete |

1. Deploy new Vercel project: `NEXT_PUBLIC_CITY=Conroe`, `NEXT_PUBLIC_STATE=TX`
2. Point `conroesignal.com` at it
3. Same Django API + Supabase database (all tables have `city`/`state` fields)
4. Add businesses for new city via Django admin or vendor signups
